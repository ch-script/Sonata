# VERSION 0.3

## What's new?

### 0.300

- **Bye Fish**: We dropped the dependency on Fish shell. `snt` now runs on native POSIX Bash out of the box, making it much more portable and easier to run on minimal environments.

- **Major codebase refactor (Rust Workspaces)**: The entire codebase was restructured into a multi-crate Rust workspace (`orchestrator`, `interface`, etc.). This cleanly separates responsibilities and stops the code from turning into a mess as the project grows.

- **Initial Orchestration System (Service Manager / Process Supervisor)**: This is the biggest step forward in 0.3. I'm laying down the foundation for an actual service manager:
  - **Declarative State**: Workspaces and commands are now stored and managed via clean TOML definitions.
  - **Runner Generation**: Dynamically compiles workspace commands into self-contained executable shell scripts (`chmod +x`).
  - **Asynchronous Execution**: Launched tasks now run as non-blocking background processes.

- **Quick Installer Script (`install.sh`)**: Setting up `snt` from scratch is way easier now. Fetch and run the new `install.sh` script to get everything downloaded and set up automatically.

### 0.301

- Cli tables don't have a 2 level limit now. You can nest [a.b.c.d.e] if you want, and the CLI will navigate it! This is mostly a change for **CUSTOMS** function.
- An add remote tcp stream execution is now supported via 'target' property. If you want to use it, go check the [CONFIG.md](../../CONFIG.md) file. It shows how.
- Now there's the option to add an "include" header at the start of every readable file. This helps if you have a set of customs commands and wish to connect them declaratively to your custom configs. Also, whilst it is declarative, you can surely go with a command by the following rules.
 If you run:
  ```bash
  snt --allow customs
  ```
  `init_customs` will create the file and append `include = "./customs.toml"` to the end of `config.toml`.
  
  If you run:
  ```bash
  snt --include binds.toml --in customs.toml
  ```
  the system will inject `include = "binds.toml"` into `customs.toml`, keeping everything good. If you pass two files at once:
  ```bash
  snt --include a.toml b.toml
  ```
  it will merge them into an array: `include = ["a.toml", "b.toml"]`.
